# Resumen del día — 24/07/2026

## Manejo de reservas por movimientos dentro de SIGA
Se armó todo el circuito para reservar mercadería y que cada reserva quede vinculada a un número de movimiento de SIGA. Ese número acompaña la orden desde que se reserva hasta que se cierra, así siempre se sabe qué se apartó, con qué movimiento y en qué estado está. Incluye poder anular una reserva y liberar la mercadería si se hizo por error.

## Medidas de seguridad para evitar conflictos entre órdenes
Se agregaron controles para que, dentro de un mismo día, las órdenes nuevas no pisen ni rompan a las que ya estaban reservadas o trabajadas. En concreto: no se puede borrar ni modificar una orden ya reservada o trabajada, al borrar un plan completo las reservas se conservan, y una reserva nueva solo suma las órdenes que todavía no tenían movimiento (no duplica las viejas).

## Manejo de conciliación en producción
Se armó el cierre de las reservas: al conciliar, el sistema compara lo reservado contra lo realmente usado y genera el ajuste correspondiente en SIGA (lo usado sale, lo sobrante vuelve). Las reservas ya cerradas pasan a un historial para no mezclarse con las pendientes, y el cierre es a prueba de repeticiones (no genera el movimiento dos veces si se reintenta).

## Puesta a punto del sistema
- **Acceso por usuarios:** se agregó el ingreso con usuario y contraseña, y ahora se pueden dar permisos a cada persona desde un centro de control (quién puede ver o usar cada parte del sistema).
- **Refactorización del directorio de trabajo:** la versión de pruebas y la de uso real quedaron conectadas, para poder pasar los cambios de una a otra con mucha más facilidad.
